# 缺陷跟进

## 定时运行

外部框架周期性执行 `aspeed schedule tick`，其中包含同步、规则扫描、操作恢复与视图重建。单独执行：

```bash
aspeed sync run aone --scope <项目>
aspeed defects scan
```

`defects scan` 的行为：

- 规则：缺负责人 → 协调人；缺期限 / 临期 / 逾期 → 负责人；逾期超过阈值 → 升级给协调人；已修复但没有回归结果 → 协调人；回归通过/失败 → 登记关闭/重新打开的 Aone 流转意图。
- 去重键 = (缺陷, 检查项, 接收人, 时间窗)：重复扫描不会重复提醒。
- 每人每日提醒有上限，超出的记为 `deferred`。
- 执行模式由 `control/policy.yaml` 决定：默认 `dry_run`（影子模式，只记录，出现在日报的“待决策事项”中供协调人评估规则）。

## 回答“哪些缺陷需要关注”

```bash
aspeed defects check          # 只评估，不写入
aspeed sync status            # 数据截止时间
```

按“无人认领 / 逾期 / 临期 / 待验证”分组回复，每条附 Aone 链接，并注明数据截止时间。

## 关闭与重新打开

- 修复后进入待验收；关联的回归（测试计划的 `defects` 字段）通过 → 登记流转到 `close_status`；失败 → 关联证据并登记重新打开。
- 这些流转默认需要协调人或验收人确认（`aspeed op approve`）。
- 无法由规则判定的情况（例如证据不充分），交给验收人，不要自行关闭。

## 不要

- 不要绕过 `defects scan` 自行发送提醒。
- 提醒措辞不要带指责；说明下一步和可以求助的人。
